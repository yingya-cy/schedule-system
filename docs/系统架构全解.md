### AI 路由：`src/routes/ai-counsel.ts`

**核心端点：**

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/counsel/stream` | **SSE 流式对话**（最主要的端点） |
| POST | `/counsel/sessions` | 创建新对话 |
| GET | `/counsel/sessions` | 获取历史对话列表 |
| GET | `/counsel/sessions/:id/messages` | 获取某对话的消息 |
| POST | `/counsel/sessions/:id/messages` | 保存消息 |
| DELETE | `/counsel/sessions/:id` | 删除对话 |
| POST | `/counsel/auto-title` | AI 生成标题 |
| POST | `/counsel/followups` | 生成追问建议 |
| POST | `/counsel/profile-summary` | 提取用户画像 |

**SSE 流式对话流程：**

```
1. 验证 messages 参数
2. 保存用户消息到 MySQL
3. 检查后端选择 (AI_COUNSEL_BACKEND)
4a. Dify 路径：
    - 查用户画像 (MySQL + req.body.profile)
    - 构建 Dify 请求 (inputs: username, department, grade, ..., teaching_week, user_context)
    - 注入 conversation_id (多轮记忆)
    - fetch POST ${DIFY_URL}/v1/chat-messages (stream)
    - 逐行解析 SSE → 提取 chunk → res.write 给浏览器
    - 记录 conversation_id 到 Map
4b. Flask 路径：
    - 构建 body (messages, profile, user_context, teaching_week, current_date)
    - fetch POST ${FLASK_URL}/api/ai/counsel/stream
    - pipe 响应流到浏览器
5. 浏览器收到 SSE chunk → AiCounselPage 消费 → 渲染 Markdown
```

### ai_counsel.py 核心逻辑

```
counsel_stream() 被调用
  → 提取最后一条用户消息
  → _build_system_prompt()
      → COUNSEL_SYSTEM_PROMPT (心理陪伴 + 校园导航 双角色)
      → CAMPUS_SUMMARY (各校区信息自然语言摘要)
      → 当前日期 + 教学周 (Express 传入)
      → 用户画像 (Express 传入)
      → _search_kb(用户消息) (本地关键词检索)
          → 滑动窗口提取 2-4 字中文关键词
          → 遍历 570 篇 KB 文章
          → 标题命中 +10 分，正文命中 +1 分
          → 返回 top 3
      → KB 结果注入 prompt
  → ai_stream(system_prompt, messages)
      → OpenAI 兼容 API (DeepSeek V4)
      → stream=True
      → yield 每个 chunk
      → 过滤 <think> 标签
  → SSE 格式输出
```

### 知识库本地检索

```
_load_kb()
  → 读取 /app/dify-kb/*.txt
  → 第一个 section (结构化头): 提取中文纯文本 → "校园生活信息总览"
  → 后续 section: 按 === 分割 → 每篇存 title + text[:2000]
  → 总共 ~570 篇

_search_kb(query)
  → 滑动窗口提取中文关键词 (2-4字)
  → 对每篇文章打分
  → 返回 top 3
```

## 8. 认证系统：JWT

### Token 生命周期

```
1. 登录: POST /api/auth/login { username, password }
   → bcrypt.compare(password, hash)
   → 生成 JWT: { userId, username, role, department }
   → 签名密钥: JWT_SECRET 环境变量
   → 返回 { token } 给前端

2. 前端: localStorage.setItem('auth_token', token)

3. 后续请求:
   前端: fetch(url, { headers: { Authorization: 'Bearer ' + token } })
   Express: authenticate 中间件
     → jwt.verify(token, JWT_SECRET)
     → req.user = decoded

4. Token 无过期时间（简化实现）
```

### 前端请求模式

```typescript
// src/services/aiCounselApi.ts
async function request<T>(url: string, options?: RequestInit): Promise<T> {
  const token = localStorage.getItem('auth_token');
  const res = await fetch(`/api/ai${url}`, {
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
    },
    ...options,
  });
  const json = await res.json();
  if (!json.success) throw new Error(json.error);
  return json.data;
}
```

## 9. SSE 流式输出

### 什么是 SSE

Server-Sent Events — 服务端单向推送文本流。比 WebSocket 简单，不需要双向通信，适合 AI 流式回复。

### 完整链路

```
DeepSeek API (SSE) → Flask/Dify → Express (代理) → 浏览器 (EventSource)
```

### Express 端

```typescript
// 设置 SSE 响应头
res.setHeader('Content-Type', 'text/event-stream');
res.setHeader('Cache-Control', 'no-cache');
res.setHeader('Connection', 'keep-alive');
res.setHeader('X-Accel-Buffering', 'no'); // 禁用 Nginx 缓冲

// 读上游流
const reader = response.body.getReader();
const decoder = new TextDecoder();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  res.write(`data: ${JSON.stringify({ chunk: text })}\n\n`);
}
res.end();

// 客户端断开 → 中止上游
req.on('close', () => controller.abort());
```

### 前端端

```typescript
const response = await fetch('/api/ai/counsel/stream', { ... });
const reader = response.body.getReader();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  // 解析 SSE 行: "data: {...}\n\n"
  for (const line of text.split('\n')) {
    if (line.startsWith('data: ')) {
      const data = JSON.parse(line.slice(6));
      if (data.chunk) fullResponse += data.chunk; // 累积
      if (data.done) break; // 结束
    }
  }
}
```
